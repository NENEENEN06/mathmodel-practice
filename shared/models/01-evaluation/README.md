# 01 评价类

**什么时候来这儿**：要在一堆方案/地区/年份里排序、打分、选优，或者要确定指标权重。

| 文件 | 模型 | 用来干什么 | 权重来源 |
| --- | --- | --- | --- |
| `ahp.py` | 层次分析法 | 把"哪个指标更重要"量化，附一致性检验 | 主观（判断矩阵） |
| `topsis.py` | 熵权法 + TOPSIS | 多指标多方案排序 | 客观（信息熵）；也可自己传权重 |
| `fuzzy_evaluation.py` | 模糊综合评价 | 指标带模糊性、要定级（优/良/中…） | 传进来（AHP 或熵权法算的） |

## 怎么选

- 有明确数据、只想排序 → **熵权法 + TOPSIS**（客观，能说清依据）。
- 指标重要性有专业判断、数据不足 → **AHP**（主观，但要过一致性检验 CR < 0.1）。
- 两者都要 → 组合赋权：`W = α·W_ahp + (1-α)·W_entropy`，α 取 0.5 是常见做法，论文里要写清理由。
- 评价等级是"好/较好/一般"这种话 → **模糊综合评价**。

## 常用组合拳

```
原始数据 → 正向化/标准化 → 权重（AHP/熵权/组合）→ 综合评价（TOPSIS/模糊）→ 排序 + 灵敏度分析
```

灵敏度分析别偷懒：把权重上下浮动 10%（或换几种赋权方式），看排名稳不稳——稳，结论才站得住。

## 坑

- **量纲**：不标准化直接算，量级大的指标会独占结果。
- **成本型指标**：忘了正向化，排名会反着来（`topsis.py` 里用 `kinds` 指定）。
- **熵权法的前提**：指标取值差异越小权重越小——全是相同值的指标熵最大、权重趋 0，这是对的，不是 bug。
- **AHP 的 n**：指标别超过 9 个，两两比较次数是 $n(n-1)/2$，人脑扛不住。
- 负值数据不能直接取对数/算熵，先平移（`topsis.entropy_weights` 已处理）。

## 跑一遍

```bash
python ahp.py                 # 判断矩阵 → 权重 + 一致性
python topsis.py              # 5 个方案的排序表
python fuzzy_evaluation.py    # 隶属度矩阵 → 等级
```
